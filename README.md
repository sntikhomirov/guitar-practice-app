# Гитарные упражнения

Небольшое desktop-приложение на Python/Tkinter для занятий на гитаре.

История изменений ведётся в `CHANGELOG.md`, релизы отмечаются git-тегами.

## Возможности

- счётчик удачных и неудачных попыток;
- подсчёт текущих серий удач/ошибок;
- подсказка, когда прибавлять или убавлять сложность;
- журнал занятий;
- добавление упражнений с названием и описанием;
- запись темпа, длительности и даты занятия;
- просмотр журнала в виде таблицы с максимальными темпами;
- сортировка упражнений в таблице по максимальному темпу, приведённому к четвертям;
- сохранение занятия из счётчика попыток в журнал;
- генерация плана занятия по журналу;
- отображение плана на экране счётчика и автозаполнение формы текущего упражнения.

## План занятия

План занятия формируется из списка упражнений в журнале.
Он отображается на экране счётчика, чтобы во время занятия не переключаться между вкладками.

Сортировка упражнений:

1. по возрастанию количества записей за последние 7 дней;
2. по возрастанию максимального темпа, приведённого к четвертям;
3. по названию упражнения.

Стартовый темп предлагается от последней записи упражнения:

```text
стартовый темп = ceil(последний BPM × 0.9)
```

Длительность стартового темпа остаётся такой же, как в последней записи.
Форма сохранения результата автоматически заполняется первым упражнением из плана.
После сохранения результата упражнение исчезает из сегодняшнего плана, а форма переключается на следующее.

## История упражнения

На вкладке «Журнал занятий» выберите упражнение в поле «История упражнения»
и нажмите «Открыть историю». В отдельном окне показаны все записи: дата,
темп, приведённый темп, удачные и неудачные попытки.

Выберите запись, измените поля и нажмите «Сохранить изменения».
«Удалить запись» удаляет только выбранную запись после подтверждения.
Изменения сохраняются в журнал, таблица и план обновляются автоматически.
Если счётчик уже содержит попытки, его форма не перезаполняется.

## Архив упражнений

На вкладке «Журнал занятий» выберите упражнение в списке истории и нажмите
«В архив». После подтверждения оно исчезнет из активного журнала, плана,
карточек целей и списков выбора. Записи, описание, недельные и общая цели сохраняются.

Кнопка «Архив упражнений» открывает список архивных упражнений.
Выберите упражнение, чтобы открыть его историю (включая исправление записей)
или нажать «Восстановить». Оно снова станет активным; обычные правила плана
продолжат действовать — отработанное сегодня или с выполненной недельной целью
упражнение не появится в плане сразу после восстановления.

Текущее упражнение с несохранёнными попытками нельзя архивировать:
сначала сохраните результат или сбросьте счётчик. Имя архивного упражнения
остаётся занятым — вместо создания дубликата восстановите его из архива.
В старых журналах отсутствие `archived` означает активное упражнение.

## Цели упражнений

На вкладке «Цели» расположены карточки упражнений с двумя прогресс-барами:

- **Общая цель (total)** — сравнение с максимумом за всю историю.
- **Недельная цель** — сравнение с максимумом своего цикла **среда–вторник**,
  без учёта старых рекордов и записей с будущей датой.

Максимум за всю историю показан один раз под названием упражнения.
В каждой секции показаны прогресс-бар, цель и процент её достижения.
Карточки размещены в сетке без полос прокрутки; число колонок зависит от ширины окна.

Нажмите «Задать» или «Изменить» в нужной секции и укажите BPM и длительность.
«Убрать цель» удаляет выбранную цель, но сохраняет упражнение и записи.
Прошлые недельные цели доступны через выбор цикла в верхней части вкладки.
В среду начинается новый цикл: цель нужно задать заново, старая не переносится.

Прогресс считается как `максимальный приведённый темп / приведённая цель × 100%`.
Например, максимум `60 / 8т` и цель `100 / 8` дают `180 / 200 = 90%`.
При достижении или превышении цели показывается `100% ✓`; без цели — `—`,
а при отсутствии записей с заданной целью — `0%`.
После записи результата, редактирования или удаления записи прогресс обновляется.
Из плана исключаются упражнения с достигнутой целью текущего недельного цикла.
При повышении цели упражнение возвращается в план, если сегодня оно ещё не отрабатывалось.
Достижение общей цели не исключает упражнение из плана; без недельной цели оно остаётся.

Старые журналы без целей поддерживаются. Одиночная цель из прежнего формата
(`target_tempo` и `target_duration`) трактуется как недельная цель текущего цикла.
Дата её цикла закрепляется при следующем сохранении журнала.
Недельные цели сохраняются в `weekly_goals`, общая — в
`total_target_tempo` и `total_target_duration`.

## Запуск

```bash
python3 counter.py
```

Альтернативный запуск:

```bash
python3 -m guitar_practice_app
```

## Тесты

```bash
python3 -m unittest
```

## Структура проекта

```text
counter.py                 # точка входа
guitar_practice_app/       # код приложения
  gui.py                   # Tkinter-интерфейс
  goals_ui.py              # карточки прогресса и редактор целей
  cycles.py                # недельные циклы среда–вторник
  models.py                # модели данных
  services.py              # бизнес-логика
  settings.py              # настройки приложения
  storage.py               # чтение/запись JSON
tests/                     # тесты
CHANGELOG.md               # история версий
BACKLOG.md                 # список будущих доработок
```

## Данные

Журнал занятий хранится локально в файле `journal_data.json` рядом с приложением.
Этот файл добавлен в `.gitignore`, чтобы личные записи случайно не попали в репозиторий.

Пример структуры данных есть в `journal_data.example.json`.

## Темпы и длительности

Для сравнения темпов разные длительности приводятся к четвертям:

| Длительность | Отображение | Коэффициент |
|---|---:|---:|
| четверти | `4` | `1` |
| восьмые | `8` | `2` |
| восьмые триоли | `8т` | `3` |
| шестнадцатые | `16` | `4` |
| шестнадцатые триоли | `16т` | `6` |

Приведённый темп считается как `BPM × коэффициент`.
Например, `55 / 8т` отображается в строке максимумов как `55 / 8т (=165)`.

## Процесс разработки

- Основная ветка: `master`.
- Новые изменения делаются в ветках `feature/...`.
- В `master` изменения попадают через Pull Request.
